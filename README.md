# 群聊 Bot 限流

用来防止群聊Bot中无限互相@烧token的小插件，可以通过```/bot限流 标记 @对方 [次数]```的命令来设置本方Bot在设定时间内最多回复另一个Bot几次。Bot互聊其实还挺好玩的，因此不打算一刀切，此插件保留了Bot互相对话的可玩性，也能防止无限互聊的问题。

管理员把容易互相触发的账号标记为 Bot 后，当前 AstrBot 默认在最近 60 分钟内最多回复该账号 3 轮。可以为各 Bot 单独设置不同的次数，包含 0 次（静默不回复）。超限后静默拦截，不发送可能再次触发对方的限流提示。

## 使用

在插件管理上传 ZIP 并启用。进入插件设置可调整「统计时长（分钟）」和「统计时长内最多回复几轮」，以及是否允许群主、群管理员管理标记。

在要管理的群里发送：

```text
/bot限流 标记 @对方 [次数]
/bot限流 取消 @对方
/bot限流 列表
/bot限流 状态 @对方
/bot限流 重置 @对方
/bot限流 帮助
```

`@对方` 也可以替换为数字用户 ID。别名为 `/机器人限流`、`/botlimit`。以上示例的 `/` 使用 AstrBot 已配置的唤醒前缀。标记、取消、列表、状态和重置仅供 AstrBot 管理员以及启用该权限的本群群主、管理员使用。列表超过 20 人时可用 `/bot限流 列表 2` 翻页。

### 每个 Bot 单独的次数（v1.2.0）

```text
/bot限流 标记 @BotA 0
/bot限流 标记 @BotB 5
/bot限流 标记 @BotC
/bot限流 标记 123456789 5
```

- 次数范围为 **0～10000 的整数**。`0` 表示不再回复该 Bot，不会在下一个统计窗口自动恢复；`5` 表示当前统计时长内最多回复 5 轮。
- 不填次数表示**跟随插件设置中的默认次数**；后续修改默认值会继续影响该 Bot。单独设置过次数的 Bot 不受默认次数修改影响。
- 对已标记的 Bot 再执行一次即可更新上限；再次标记但不填次数，会取消其单独上限并恢复跟随默认值。更新不清空已有使用计数，因此调低后可能立即达到限额。
- 各 Bot 共用插件设置中的统计时长；同一 Bot 在不同群、不同平台实例可以有不同次数。列表和状态显示各自实际生效的上限。
- “重置”只清零使用次数，保留标记及单独上限；要恢复一个 0 次 Bot 的回复，应重新标记并填写正数，或不填次数恢复默认值。
- 升级时自动补齐数据库字段，旧标记和计数保留；旧标记继续跟随默认次数。次数设置保存到同一 SQLite 数据库，重启后仍然生效。

## 计数方式

- 群和平台实例分别隔离；同一账号在另一个群不会自动被标记。
- 滚动统计最近指定分钟内的回复，没有整点重置的突发漏洞。
- 一条输入消息引出的文字、图片、语音、工具发送和分段输出算一轮。
- 只接收消息、没有准备发送实际内容时不占次数。首次发送前占用名额；接口报错或超时也保留该次计数，避免发送状态不明时重复回复。
- 并发发送会再次原子检查名额，最多放行配置的轮数。并发请求可能已经开始模型计算，发现满额后会停止发送。
- 重复标记可更新单独上限，但不会清零次数。取消标记会删除该用户在本群的记录；重置只清零次数并保留标记和上限。
- 停用插件暂停限制，已有标记和记录保留；重新启用后按当前窗口继续统计。

标记和回复时间保存在 `data/plugin_data/astrbot_plugin_group_bot_limiter/quota.sqlite3`，更新插件、重启 AstrBot 后继续生效。数据库只存平台/群/账号 ID、标记者、时间和事件 ID，不保存消息正文；历史计数最多保留 366 天，以支持调大窗口。

## 兼容范围

已针对 AstrBot 4.28.2 的 OneBot / aiocqhttp 群聊实现。覆盖标准回复、当前事件的 `event.send`、QQ 流式/分段发送，以及继承当前消息执行上下文并发到同一会话的 `context.send_message`。同轮后台语音不会重复扣次数。只包装运行时调用，不修改 AstrBot 核心文件。

本插件只管理当前 AstrBot 的回复。独立定时主动消息、外部服务自行通过 OneBot 接口发送的消息，以及绕过上述接口的插件无法可靠归属某个输入账号，不计入本插件。第三方插件如自行忽略事件停止状态，也可能绕过前置拦截。
